# Shape the offer

Read [working method](references/working-method.md). Recover the chosen customer group, observed pain, alternatives, proof, capacity, and price constraints. If no audience is chosen, resolve that first.

Build five parts: an outcome in the customer's language, how it works, genuine proof, a proposed price, and a credible way to reduce risk. Ask up to six useful questions, skipping known answers. Missing proof stays a proof gap; never fabricate a testimonial or outcome. Do not promise results, refunds, guarantees, or work the user cannot deliver.

If pricing is requested, present up to three explicit test bands with currency, terms, assumptions, and reasons from reported value or verified alternatives. Do not make an arithmetic result look like market evidence. Advice concerns the user's offer, not buying or upgrading this plugin. No transactional links or sales promotion for the plugin itself.

Read the draft as a skeptical member of the chosen audience. Raise up to five concrete objections and revise once using the evidence. Preserve accepted terms. Output the one-sentence pitch, the five offer parts, main objections, proof gaps, and one feasible next test. Mark commercial terms as proposed until the user accepts them. Update only the offer section.
